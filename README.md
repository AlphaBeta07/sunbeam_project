# Sunbeam Project (Chatbot & Web Scraper)

This project consists of an intelligent, local-AI-powered chatbot and a dedicated web scraper built for the Sunbeam Institute. The application allows users to ask questions regarding Sunbeam Institute courses, internships, and locations, retrieving answers strictly based on the provided website data through a Retrieval-Augmented Generation (RAG) architecture.

## 🛠️ Tools & Technologies Used

### Core Applications
- **[Streamlit](https://streamlit.io/):** For building the interactive graphical user interface of the chatbot natively in Python.
- **[Selenium WebDriver](https://www.selenium.dev/):** For automating the web browser in headless mode to scrape text, accordions, and tables from the Sunbeam Institute website.

### AI & NLP (RAG Architecture)
- **[LangChain](https://www.langchain.com/):** For orchestrating the Prompt, Chains, Vector Database, and Language Models.
- **[ChromaDB](https://www.trychroma.com/):** An open-source vector database used to calculate, store, and retrieve Document Embeddings. 
- **[LM Studio / Ollama](https://lmstudio.ai/):** Used to act as the Local OpenAI-compatible API endpoint hosting the LLM and Embedding models.
  - **Language Model:** `google/gemma-3n-e4b`
  - **Embedding Model:** `text-embedding-nomic-embed-text-v1.5`

### Other Libraries
- `beautifulsoup4`, `lxml`: HTML parsing.
- `unstructured`, `pypdf`: Assisting text loaders.
- `sentence-transformers`: Local embeddings processing.

## 🧠 ChromaDB & Vector Database Mechanics in Detail

The project relies heavily on **ChromaDB** as the underlying Vector Database for Retrieval-Augmented Generation (RAG). Here is a minute-by-minute breakdown of how ChromaDB is structured, hydrated, and queried within the application:

### 1. Document Ingestion & Loading
When `main.py` is initialized, the `load_vectordb()` function triggers a Langchain `DirectoryLoader` pointing to the `/data` directory. 
- It scans for all scraped files matching the `**/*.txt` glob pattern.
- It uses `TextLoader` to load the raw string content of these files, which were previously generated by the `sunbeam_scraper.py` script.

### 2. Pre-processing & Filtering
Before migrating into ChromaDB, the loaded documents undergo a custom filtering step via the `is_meaningful()` function:
- **Length Constraint:** The document text must exceed 200 characters.
- **Formatting Constraint:** The text is rejected if it is entirely in UPPERCASE.
- **Word/Spacing Constraint:** The document must contain more than 40 spaces (implying a reasonably long paragraph rather than short menu items or scraped ui buttons).
Documents that fail these checks are permanently dropped and not vectorized.

### 3. "No-Chunking" Strategy
Unlike typical RAG pipelines that use `RecursiveCharacterTextSplitter` to break large files into smaller nodes, this project intentionally adopts a **No-Chunking strategy**.
As indicated by the persistence directory `chroma_db_no_chunking`, the text files are ingested whole. This design relies on the `sunbeam_scraper.py` effectively separating scraped website sections (such as targeted accordions and standard tables) into individual bite-sized `.txt` files a-priori.

### 4. Vector Embeddings Generation
The filtered whole documents are passed to LangChain's `OpenAIEmbeddings` wrapper.
- **Model:** `text-embedding-nomic-embed-text-v1.5`
- **Host:** Running locally on `http://127.0.0.1:1234/v1` (via LM Studio/Ollama).
- **API Key:** A `"dummy"` key is used since the inferencing is entirely local.
- **Context Length Checking:** `check_embedding_ctx_length=False` is set to bypass arbitrary token limits, assuming the Nomic-embed model can handle the individual `.txt` file lengths natively.

### 5. Persistence & Storage
ChromaDB is initialized and populated using `Chroma.from_documents(...)`.
- It processes the valid text strings, calls the local Nomic embeddings model to fetch numerical representation vectors, and stores both the original document metadata and its vector array locally.
- **Storage Location:** It creates SQLite databases and binary storage files strictly inside the `chroma_db_no_chunking` system directory. This ensures the application caches the data, securely skipping the expensive embedding calculations on subsequent server startups.

### 6. Retrieval Configuration
When the user submits a chat query, the application turns the persisted ChromaDB instance into a LangChain retriever (`vectordb.as_retriever(...)`):
- **Search Type:** Configured for standard `"similarity"` search, which mathematically compares the input query vector against the stored document vectors.
- **Search Kwargs:** The parameter `{"k": 3}` instructs ChromaDB to return the top 3 most relevant un-chunked `.txt` documents related to the user's query. Those 3 documents are subsequently concatenated and pushed into the final Prompt prompt as RAG `context` for the primary Gemma LLM.

## 📂 Project Structure

- `main.py`: The main Streamlit web application. Loads the vector database, connects to the local LLM server, and handles the chat UI and RAG pipeline.
- `sunbeam_scraper.py`: A Selenium automation script that visits `https://www.sunbeaminfo.in/internship` to extract visible text, hidden accordion text, and tables into organized `.txt` files.
- `data/`: The directory where the extracted `.txt` documents are stored by the scraper.
- `chroma_db_no_chunking/`: The persisted ChromaDB directory storing the embedded vectors.
- `requirements.txt`: Contains all the Python package dependencies.
- Images (`logo.png`, `assistant_logo.png`, `user.png`): Application UI assets.

## ⚙️ Installation & Setup Prerequisites

### 1. Python Environment Setup
We recommend using Python 3.9+ along with a virtual environment.

```bash
# 1. Navigate to the project directory
cd path/to/sunbeam_project

# 2. Create a virtual environment (optional but recommended)
python -m venv venv

# 3. Activate the virtual environment
# On Windows:
venv\Scripts\activate
# On Mac/Linux:
source venv/bin/activate

# 4. Install the required dependencies
pip install -r requirements.txt
```

### 2. Local LLM Server Setup
Since this project runs local LLMs using an OpenAI-compatible API, you will need to host your models locally.

1. Download and open [LM Studio](https://lmstudio.ai/) (Or any other local host like Ollama).
2. Download the models from HuggingFace inside your local host:
   - Text generation model: `google/gemma-3n-e4b` (or equivalent)
   - Embeddings model: `text-embedding-nomic-embed-text-v1.5` (or equivalent)
3. Start the Local Inference Server on `http://127.0.0.1:1234/v1`. The script explicitly assumes the server runs on port 1234.

### 3. Selenium WebDriver
Ensure that you have [Google Chrome](https://www.google.com/chrome/) installed. The script uses Selenium WebDriver in headless mode.

## 🚀 How to Run

### Step 1: Scrape the latest Data (Optional)
If you want to fetch or refresh the data directly from the Sunbeam Institute website, run the scraper script.
```bash
python sunbeam_scraper.py
```
This will open Chrome dynamically, parse the website sections, and save text file content into the `data/` folder.

### Step 2: Start the Chatbot UI
Once your local LLM server is running (port 1234), execute the Streamlit app.
```bash
streamlit run main.py
```
This command will initialize the Chatbot interface on a local browser tab (typically `http://localhost:8501`). On the first run, it will read files from the `data/` folder and persist the vector embeddings into a `chroma_db_no_chunking` folder.

## 💡 Usage Example Features
- **Sidebar Chat History**: Start a new chat session at any time. Previous chats remain available in the sidebar memory.
- **Quick Prompts**: Clickable bubbles to instantly ask frequently asked questions ("Tell me about sunbeam", "Location", etc.).
- **Smart Switch**: If a question doesn't relate to Sunbeam, the bot smartly attempts to bypass the RAG context to act as a general AI assistant, preserving conversation flow.
